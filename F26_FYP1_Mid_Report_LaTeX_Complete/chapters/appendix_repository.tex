\section{Branch Strategy}
\begin{itemize}
    \item \texttt{master}: the integration branch, and the default branch.
    \item Feature branches (e.g.\ \texttt{ci/github-actions}, \texttt{ci/pipeline-updates}, \texttt{exp/trainer-arkitscenes}): short-lived branches for specific work items.
    \item Branches are merged locally rather than through pull requests. The pull request template exists and CI runs on feature branches, but the merges themselves were not raised as PRs, so the ``Pull request'' column in Figure~\ref{fig:repobranches} is empty. Adopting PR-based merges is an action for FYP-2.
\end{itemize}

Each row shows a branch's check status and its ahead/behind count against \texttt{master}. Feature branches carry passing checks; the failing status on \texttt{master} is the hygiene job described in Section~\ref{sec:cicdevidence}.

\section{CI/CD Evidence}
\label{sec:cicdevidence}
The GitHub Actions CI pipeline runs on pushes to non-\texttt{master} branches and on pull requests; direct pushes to \texttt{master} are covered by the CD workflow instead.
\begin{enumerate}
    \item \textbf{Python checks}: ruff lint + pytest on Python 3.10, 3.11, 3.12.
    \item \textbf{Web build}: Node.js build of the web UI (placeholder for FYP-2).
    \item \textbf{Android build}: Gradle APK build.
    \item \textbf{Hygiene}: File size limits, secrets detection, workflow lint.
\end{enumerate}

The CD pipeline triggers on push to master (build artifacts) and on version tags (GitHub Release with APK and web bundle).

CI passes on the feature branches. The failing runs on \texttt{master} are the CD workflow's hygiene job, which rejects a tracked \texttt{.env}. That file has since been untracked and ignored, and the key it held must still be rotated (NFR-S2, recorded as not met).
