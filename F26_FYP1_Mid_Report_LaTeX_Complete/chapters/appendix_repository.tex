\section{Branch Strategy}
\begin{itemize}
    \item \texttt{master}: Stable, CI-passing code. All merges go through pull requests.
    \item Feature branches (e.g., \texttt{ci/github-actions}): Short-lived branches for specific work items, merged via PR with CI checks.
\end{itemize}

\section{CI/CD Evidence}
The GitHub Actions CI pipeline runs on every push and pull request:
\begin{enumerate}
    \item \textbf{Python checks}: ruff lint + pytest on Python 3.10, 3.11, 3.12.
    \item \textbf{Web build}: Node.js build of the web UI (placeholder for FYP-2).
    \item \textbf{Android build}: Gradle APK build.
    \item \textbf{Hygiene}: File size limits, secrets detection, workflow lint.
\end{enumerate}

The CD pipeline triggers on push to master (build artifacts) and on version tags (GitHub Release with APK and web bundle).
