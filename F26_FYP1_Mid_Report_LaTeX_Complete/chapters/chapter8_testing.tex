\chapter{Testing and Early Validation}

\section{Testing Strategy}
Our testing strategy combines automated unit/integration tests (CI-enforced) with manual system-level validation on real indoor scans. The rationale is that unit tests verify algorithmic correctness (coordinate transforms, file parsing, API contracts), while end-to-end validation on real data verifies reconstruction quality and metric accuracy---properties that cannot be unit-tested.

\begin{itemize}
    \item \textbf{Unit tests}: Python pipeline modules tested with pytest on small synthetic capture folders (Python 3.10, 3.11, 3.12; no GPU, network or phone needed). Run by GitHub Actions CI on pushes to non-master branches, on pull requests, and from the CD workflow.
    \item \textbf{Lint}: ruff in CI; real errors fail the run, unused-code findings are informational only.
    \item \textbf{Integration tests}: Server endpoint tests through the FastAPI test client with the job starters replaced by recorders (upload, status, download, config), and RunPod client tests with the network faked. No test runs against a live RunPod pod.
    \item \textbf{Android}: There are \textbf{no Android (Java) unit tests}. The capture app is checked by using it on a phone, and its packaging by the APK/manifest checker tests.
    \item \textbf{System tests}: Manual runs of the reconstruction pipeline on real recordings, followed by held-out evaluation and tape-measure comparison. The full app upload $\rightarrow$ server $\rightarrow$ RunPod $\rightarrow$ download path has not yet been run as a recorded test.
    \item \textbf{Regression tests}: Each pipeline change is compared on the same two reference recordings (the first room, \texttt{newRoomAttemptSadness}, and a second room, \texttt{roomAttemptSadness2}) to detect quality regressions. This comparison is run by hand with the evaluation scripts, not in CI.
\end{itemize}

\section{Test Results}

\paragraph{Automated tests (CI):}
The pytest suite has 128 test functions in 12 files (one of them parametrised over every Python file). In CI run \#6 the unit-test step succeeded on Python 3.10, 3.11 and 3.12, the blocking ruff lint (real errors only) passed, and the whole run took about two minutes. Of the 20 test cases above, 12 are backed by these automated tests (TC-6 is also checked by tape measure), 2 by recorded manual runs (TC-5, TC-13), 2 are only partly executed (TC-11, TC-12), 3 Android cases have no automated test (TC-1 to TC-3), and TC-14 has not been executed. CI runs on every push to non-master branches, on pull requests, and from the CD workflow on \texttt{master}; it has not yet been re-run on the current \texttt{master} head.

\section{Acceptance Testing / Validation}
Acceptance testing validates the system against the success criteria defined in Section~1.9:

\begin{enumerate}
    \item \textbf{Metric accuracy}: Four rigid-object distances measured in the model agree with a tape measure to a mean of 4.8\,mm (0.19\%) and a worst case of 0.29\% (Table~\ref{tab:tape}), against a 5\% target.
    \item \textbf{Reconstruction quality}: v6 scores 26.52\,dB PSNR / 0.8886 SSIM on 42 held-out frames of the first room, clearing the 25\,dB / 0.85 thresholds; the second room reaches held-out SSIM 0.91 (its PSNR is not yet measured). Views from the room centre, where no camera stood, are coherent, and the earlier ghosts and floating splats are gone.
    \item \textbf{Processing time}: The measured end-to-end time is approximately 75 minutes on the development RTX 3070 (feature matching 23\,min, mapping 6\,min, training 45\,min). The NFR-P1 target of under 35 minutes on an RTX 4090 is a projection for FYP-2 and has not yet been measured, so NFR-P1 is not yet verified.
    \item \textbf{Capture usability}: Not yet formally evaluated. Usability testing with external users is planned for FYP-2.
\end{enumerate}

\section{Edge and Failure Cases}

\begin{enumerate}
    \item \textbf{Tracking loss during capture}: ARCore loses tracking in featureless corridors or when the phone is moved too fast. The app displays a red ``Tracking Lost'' banner and pauses quality logging. The pipeline's IMU fallback (\texttt{fallback.py}) bridges short gaps ($<$2\,s); longer gaps cause SfM failure. \textit{Mitigation}: Live IQA warns the user to slow down; coverage overlay shows unscanned areas.

    \item \textbf{Plain white walls}: Rooms with large untextured surfaces produce sparse SfM point clouds in those regions. The model shows blurring or holes on plain walls. \textit{Mitigation}: The IQA ``low texture'' warning prompts the user to capture textured objects nearby.

    \item \textbf{Mirrors and glass}: Highly reflective surfaces cause incorrect depth estimates and SfM outliers. \textit{Status}: Known limitation; documented for FYP-2 investigation.

    \item \textbf{Network interruption during upload}: If the HTTP connection drops mid-upload, the app (\texttt{ProcessingActivity}) displays an error with a retry button. On the server, an upload missing a required file or carrying a corrupt depth zip is rejected cleanly (TC-8). \textit{Status}: Partly handled; an interrupted upload has not been tested end to end.

    \item \textbf{RunPod pod failure}: If SSH never becomes ready (pod crash, GPU unavailable), \texttt{wait\_for\_ready} gives up after 300\,s (polling every 10\,s), the pod is terminated in the \texttt{finally} block, and the job is marked failed. \textit{Status}: Implemented; the timeout is unit-tested with a faked API (TC-7), but the termination path has not yet been exercised on a live pod.
\end{enumerate}

\section{Current Validation Status}
Status of the Iteration~1 acceptance criteria (core pipeline complete, refinement ongoing):
\begin{itemize}
    \item \checkmark\ Reconstruction quality: v6 scores 26.52\,dB / 0.8886 on the first room ($\geq$25\,dB, $\geq$0.85). Second room: SSIM 0.91; PSNR not yet measured.
    \item \checkmark\ Metric accuracy: mean 0.19\%, worst case 0.29\% against the 5\% target (Table~\ref{tab:tape}).
    \item Processing time: \textit{not yet verified}. Measured $\sim$75\,min on RTX 3070; the $<$35\,min RTX 4090 target (NFR-P1) is projected and not yet measured.
    \item Pod lifecycle: \textit{partly verified}. \texttt{terminate\_pod()} is called from \texttt{finally} blocks and the client calls are unit-tested with a faked API; a live-pod test is not yet executed.
    \item \checkmark\ CI pipeline: all automated tests passed in CI run \#6 on Python 3.10--3.12; blocking ruff lint passed.
    \item Not yet automated or executed: Android unit tests (TC-1 to TC-3), processing timeout (TC-14), app-to-RunPod end-to-end run.
\end{itemize}

Remaining validation for FYP-2:
\begin{itemize}
    \item Measurement accuracy on $\geq$3 additional rooms with varied geometry.
    \item Structural-layer accuracy: wall lengths against tape measure and detected doors against a manual count.
    \item Web viewer usability testing with external users.
    \item Stress testing: large rooms, long recordings ($>$10 minutes), low-end Android devices.
\end{itemize}
