\chapter{Testing and Early Validation}

\section{Testing Strategy}
Our testing strategy combines automated unit/integration tests (CI-enforced) with manual system-level validation on real indoor scans. The rationale is that unit tests verify algorithmic correctness (coordinate transforms, file parsing, API contracts), while end-to-end validation on real data verifies reconstruction quality and metric accuracy---properties that cannot be unit-tested.

\begin{itemize}
    \item \textbf{Unit tests}: Python pipeline modules tested with pytest (3 Python versions: 3.10, 3.11, 3.12). Run on every push and pull request via GitHub Actions CI.
    \item \textbf{Lint}: ruff static analysis enforced in CI; blocks merge on violations.
    \item \textbf{Integration tests}: Server endpoint tests (upload, status polling, config switching).
    \item \textbf{System tests}: Manual end-to-end validation: phone capture $\rightarrow$ upload $\rightarrow$ cloud processing $\rightarrow$ model viewing $\rightarrow$ metric verification.
    \item \textbf{Regression tests}: Each pipeline change is validated against the same two reference scans (Room~A: 4.2$\times$3.1\,m bedroom, Room~B: 5.0$\times$3.5\,m living room) to detect quality regressions.
\end{itemize}

\section{Acceptance Testing / Validation}
Acceptance testing validates the system against the success criteria defined in Section~1.9:

\begin{enumerate}
    \item \textbf{Metric accuracy}: Room dimensions measured in the 3D model match tape-measure ground truth within 2\,cm for rooms up to 5\,m in each dimension. Sim3 scale factor is consistently 1.000--1.003$\times$.
    \item \textbf{Reconstruction quality}: Held-out PSNR exceeds the 25\,dB threshold on both test rooms. Novel views are visually coherent with no ghosting or significant artifacts.
    \item \textbf{Processing time}: End-to-end processing completes in under 15 minutes on an RTX 3090, meeting the NFR-P1 requirement.
    \item \textbf{Capture usability}: Three users (team members) successfully captured rooms on first attempt using only the app's live IQA guidance, with no prior training.
\end{enumerate}

\section{Edge and Failure Cases}

\begin{enumerate}
    \item \textbf{Tracking loss during capture}: ARCore loses tracking in featureless corridors or when the phone is moved too fast. The app displays a red ``Tracking Lost'' banner and pauses quality logging. The pipeline's IMU fallback (\texttt{fallback.py}) bridges short gaps ($<$2\,s); longer gaps cause SfM failure. \textit{Mitigation}: Live IQA warns the user to slow down; coverage overlay shows unscanned areas.

    \item \textbf{Plain white walls}: Rooms with large untextured surfaces produce sparse SfM point clouds in those regions. The model shows blurring or holes on plain walls. \textit{Mitigation}: The IQA ``low texture'' warning prompts the user to capture textured objects nearby.

    \item \textbf{Mirrors and glass}: Highly reflective surfaces cause incorrect depth estimates and SfM outliers. \textit{Status}: Known limitation; documented for FYP-2 investigation.

    \item \textbf{Network interruption during upload}: If the HTTP connection drops mid-upload, the app displays an error with a retry button. The server discards the partial upload. \textit{Status}: Handled; no data corruption.

    \item \textbf{RunPod pod failure}: If SSH never becomes ready (pod crash, GPU unavailable), the 60\,s SSH polling timeout triggers, the pod is terminated in the \texttt{finally} block, and the job is marked failed. \textit{Status}: Handled; no billing leak.
\end{enumerate}
