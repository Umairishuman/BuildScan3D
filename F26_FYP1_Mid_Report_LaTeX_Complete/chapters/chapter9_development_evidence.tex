\section{Work Completed}
The Android capturing application has been developed (including ARCore pose, depth and quality logging features, live IQA, coverage overlay and upload interface), the reconstruction mechanism has been implemented (including IMU fallback, key frame extraction, COLMAP SfM with Sim3 metric alignment and Nerfstudio splatfacto training mechanism, model export, with gyro-aware frame selection validated but not yet in the one-command pipeline), the processing server (introducing FastAPI with local and RunPod cloud GPU options and with pod termination function), the CI/CD system (including lint, unit testing, apk and web build and hygiene testing functions), the server launcher (\texttt{start\_server.bat}, which supports \texttt{.env} files), and root-cause investigation of degenerate splat geometry (six causes, documented in \texttt{Training\_Analysis.md}).

\section{Work Remaining}
Scheduled in Chapter~\ref{ch:plan}: the Three.js/WebGPU Splat viewer with orbit controllers, point-to-point measurement, completion of the structural layer (wall-to-wall dimensions of the walls, doors and openings, ceiling height identification and floor plan export), wall snapping and floor-plan display, improvement of 3DGS (one-click pipeline of v6 version, verification of the second room, motion blur modeling based on IMU); validation in the field is to be done in 3 or more rooms, usability check will involve outside users; 3D mesh creation is in scope as planned work but not yet scheduled.

\section{Security and Privacy Considerations}
\begin{itemize}
    \item \textbf{API credential management}: The RunPod API credential is loaded at runtime from environment variables or a \texttt{.env} file and is never mentioned in the source code directly. Nonetheless, the \texttt{.env} file was not in \texttt{.gitignore} and was uploaded to the repository on the 18th of October, 2026, contrary to NFR-S2. It was untracked and added to \texttt{.gitignore} on the 22nd of October, 2026; the key committed earlier is still in the repository history and must be rotated.
    \item \textbf{CI secret scanning}: The CI hygiene job cannot pass if it keeps a \texttt{.env} file or key or certificate documents; also, it scans tracked files for private keys, AWS keys and GitHub tokens (it has no pattern for RunPod keys). The last time CI ran (run \#6) was before \texttt{.env} was committed; the file has since been untracked, so this rule no longer blocks the next CI run on \texttt{master}.
    \item \textbf{Data privacy}: The gathered scanning data is sent to the processing server via a local network. When in production, an HTTPS mode will need to be applied. Collected data can be processed and deleted via the API.
    \item \textbf{Cloud GPU security}: the RunPod pods are formed when they are needed and can only be used in a single operation; no data can be kept on the cloud GPU after.
\end{itemize}

\section{Current Limitations}
\begin{enumerate}
    \item \textbf{Mirrors and Glass}: The presence of highly reflective surfaces results in SfM outliers with an inaccurate depth model found in those areas. The planned FYP-2 experiment will attempt to detect and mask reflective surfaces.
    \item \textbf{Large Rooms}: Rooms that exceed roughly 8$\times$8 meters may exceed the GPU capacity limit when training takes place on an RTX 3070 (8\,GB). It is expected that a cloud GPU with 24\,GB of memory can handle larger scenes. However, this fact has yet to be confirmed.
    \item \textbf{Outdoor Scenes}: The system has been designed for indoor use; outdoor scenes with sky, vegetation, and long distances are beyond the system capabilities.
    \item \textbf{Real-Time Processing}: Processing takes 75 minutes on the developing RTX 3070, whereas cloud-GPU timing has yet to be carried out. Real-time processing is not possible using existing 3DGS training times.
    \item \textbf{Single-Floor Only}: The current coverage map and measurement tools rely on a single-floor environment. Multi-floor buildings require manual editing.
    \item \textbf{No Web Viewer Yet}: At the moment, 3D models can be viewed only in a desktop program. A web-based viewer based on Three.js will be developed for FYP-2.
\end{enumerate}
