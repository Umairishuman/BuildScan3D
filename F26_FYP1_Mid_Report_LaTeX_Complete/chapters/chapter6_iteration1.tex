\chapter{Iteration 1: Design and Implementation}

\section{Iteration Objectives}
Build the complete end-to-end pipeline: phone capture $\rightarrow$ automated upload $\rightarrow$ cloud GPU reconstruction $\rightarrow$ metric-scale 3D model. Validate reconstruction quality and metric accuracy on real indoor scans.

\section{Selected Use Cases / Features}
\begin{itemize}
    \item UC-1: Record Indoor Scan (with live IQA and coverage guidance)
    \item UC-2: Upload and Process (with progress tracking)
    \item UC-3: View finished model (via local viewer; web viewer deferred to FYP-2)
\end{itemize}

\section{Design}
The Iteration~1 design focused on three subsystems:
\begin{enumerate}
    \item \textbf{Capture subsystem}: ARCore session $\rightarrow$ CaptureLogger (background I/O) $\rightarrow$ QualityMonitor (frame analysis at 6\,FPS) $\rightarrow$ CoverageMap (depth $\rightarrow$ voxels $\rightarrow$ overlay).
    \item \textbf{Upload subsystem}: OkHttp multipart POST $\rightarrow$ FastAPI \texttt{/upload} $\rightarrow$ Job creation $\rightarrow$ Pipeline dispatch (local or RunPod).
    \item \textbf{Pipeline subsystem}: Six sequential steps (fallback $\rightarrow$ prepare $\rightarrow$ sfm\_colmap $\rightarrow$ export\_nerfstudio $\rightarrow$ ns-train $\rightarrow$ ns-export), each with timeout watchdog.
\end{enumerate}

\section{Implementation}
Implementation was carried out in Java (Android app) and Python (server and pipeline). Key implementation milestones:

\begin{enumerate}
    \item \textbf{Weeks 1--2}: Extended the ARCore hello\_ar\_java sample with \texttt{CaptureLogger} for sensor data recording, verified pose-to-video synchronization ($r = 0.76$--$0.79$ at 0.00\,s offset).
    \item \textbf{Weeks 3--4}: Built the COLMAP SfM pipeline (\texttt{sfm\_colmap.py}), resolved coordinate alignment issues (OpenGL $\rightarrow$ OpenCV), implemented Sim3 metric alignment, debugged lens distortion.
    \item \textbf{Weeks 5--6}: Diagnosed and fixed degenerate splat geometry (6 root causes documented in \texttt{Training\_Analysis.md}), added gyro-aware frame selection, live IQA, and coverage overlay.
    \item \textbf{Weeks 7--8}: Built the FastAPI server, RunPod cloud GPU integration, Android upload UI (\texttt{ProcessingActivity}), CI/CD pipeline.
\end{enumerate}

\section{Technical Implementation Details}

\paragraph{Pose-to-video synchronization (\texttt{CaptureLogger.java}):} ARCore's recording API writes video and poses from the same frames, but poses are only logged during \texttt{TRACKING} state, creating gaps. The pipeline interpolates poses at each frame's PTS (linear position, slerp rotation) and skips frames inside tracking gaps $> 0.12$\,s.

\paragraph{Sim3 metric alignment (\texttt{sfm\_colmap.py}):} COLMAP's global mapper produces an arbitrary-scale coordinate system. We compute a 7-DOF similarity transform (rotation + translation + scale) from matched COLMAP and ARCore camera positions using RANSAC (2{,}000 four-point samples, 10\,cm inlier threshold) followed by a Umeyama refit on the inliers; the inlier median residual is about 2.5\,cm. Because ARCore re-anchors silently, only its largest self-consistent segment ends up as inliers. Frames that jump more than 30\,cm from their temporal neighbours are dropped as SfM mis-registrations. The resulting metric scale is validated against a tape measure (Table~\ref{tab:tape}).

\paragraph{Recording fast-path (\texttt{HelloArActivity.java}):} During recording, the \texttt{onDrawFrame()} method exits early after camera feed rendering and quality overlay (at 2\,Hz). All plane detection rendering, virtual object placement, PBR lighting, cubemap filtering, and tap handling are skipped, reducing GL thread load significantly.

\paragraph{Featureless-tracking fallback (\texttt{imu.py}, \texttt{fallback.py}, \texttt{relocalize\_pnp.py}):} On plain walls ARCore loses tracking, and after re-tracking it sometimes continues in a shifted or rotated world frame. The fallback reads the gyroscope and accelerometer (201\,Hz) stored in ARCore's own recording, self-calibrates the IMU-to-camera rotation and the sensor biases, and bridges each gap: rotation by gyro integration, position by accelerometer integration with a minimal cubic correction that matches position and velocity at both ends. A heading mismatch at re-tracking reveals a new map frame, and the post-gap segment is re-aligned to the map by matching its keyframes against it (PnP). This is the team's main novelty claim. On a real recording, all three heading jumps were detected, and re-alignment cut the error of post-gap frames against earlier frames from \textbf{49.7\,px to 8.2\,px}. Limits: IMU-only position is reliable only when both ends of a gap are anchored, and re-alignment needs the user to return to an already mapped area (the app now says so during tracking loss).

\paragraph{Structural layer (\texttt{structure.py}, prototype):} The photoreal splat model is not modified. Instead the room shell is rebuilt next to it: the floor plane from the distribution of splat heights; the outermost wall on each side of the two dominant wall directions, each refined individually; corners as intersections of neighbouring walls, giving the floor polygon; per-wall textures as the median over the best views, which removes moving reflections; and openings where the cameras consistently see through a wall plane, classified as doors by their size and position. On the first room it found wall planes of 6.65--6.68\,$\times$\,4.45--4.48\,m and \textbf{detected 5 doors automatically}. Output is \texttt{structure.json} (planes, corners, dimensions, openings), the basis for automatic floor plans and 1:1 measurement. Ceiling-height detection is not yet reliable and is FYP-2 work.

\paragraph{RunPod lifecycle (\texttt{runpod\_client.py}):} The \texttt{run\_pipeline\_on\_runpod()} function wraps the entire pod lifecycle in a try/finally block. Whenever a pod was created, the \texttt{finally} clause calls \texttt{terminate\_pod()}, and a watchdog thread enforces a hard time limit, so that that even exceptions, timeouts, or SSH failures do not leave a pod running and accumulating charges.

\section{Algorithms and Technical Decisions}

\begin{enumerate}
    \item \textbf{Gyro-aware frame selection}: For each 0.2\,s window, compute predicted motion blur as $\text{blur\_px} = \omega \times t_{\text{exp}} \times f$, where $\omega$ is IMU angular velocity (rad/s), $t_{\text{exp}}$ is exposure time, and $f$ is focal length in pixels. Select the frame with minimum predicted blur. This outperforms Laplacian-based sharpness ($r = 0.20$ correlation with true blur).

    \item \textbf{Coverage map}: Discretize 3D space into 10\,cm voxels. For each voxel, track from how many of 16 directions (8 azimuth $\times$ 2 elevation) it has been observed. Display as dots: red (1 direction), yellow (2--3), green (4+). Cap processing at 5{,}000 voxels and 2{,}000 drawn dots for performance.

    \item \textbf{Degenerate splat diagnosis}: Computed per-model statistics (thickness/width median, opacity histogram, splat count) and compared against reference implementations. Identified flattening regularizer $\times$ Adam interaction as the primary cause of zero-thickness splats.
\end{enumerate}

\section{Contributions and Novelty}
\label{sec:novelty}
The contributions so far, each backed by measured evidence in this report:
\begin{enumerate}
    \item \textbf{Measured evidence of why commodity ARCore poses fail for 3DGS}---a silent $\sim$1\,m\,/\,28\textdegree\ re-anchor and a missing lens model ($k_1 \approx 0.09$, $k_2 \approx -0.22$)---and a working fix: image-based poses with ARCore kept for scale and gravity (Table~\ref{tab:posefix}).
    \item \textbf{A featureless-tracking IMU fallback}, validated on simulated gaps: 3.8\,cm error against 30.6\,cm for interpolation over 9\,s, and post-gap re-alignment from 49.7\,px to 8.2\,px (Table~\ref{tab:imufallback}).
    \item \textbf{Live capture-quality guidance and a coverage overlay in the app}: warnings for blur, fast motion, darkness and plain surfaces, a vibration alert, and a live overlay of unmapped areas.
    \item \textbf{Gyro-aware frame selection that measurably improves quality}: +0.26\,dB / +0.009 SSIM, the largest single gain on the way to v6 (Table~\ref{tab:quality}).
    \item \textbf{Millimetre-level metric accuracy from a phone video, without LiDAR}: mean 4.8\,mm (0.19\%), worst case 0.29\% against a tape measure (Table~\ref{tab:tape}).
\end{enumerate}

\section{Iteration Outcome}
Iteration~1 status: \textbf{core pipeline complete, refinement ongoing}. Results so far:
\begin{itemize}
    \item Reconstruction quality clears the 25\,dB PSNR acceptance bar: the current best model (v6) scores 26.52\,dB PSNR / 0.8886 SSIM on 42 held-out frames that no model was trained on.
    \item Metric accuracy: tape-measure mean error 4.8\,mm (0.19\%), worst case 0.29\%, against a 5\% target.
    \item Processing time is approximately 75 minutes measured on the local RTX 3070 (matching 23, mapping 6, training 45\,min). The FYP-2 target is under 35 minutes on an RTX 4090 (RunPod); this is a projection and has not yet been measured.
    \item The app provides live quality guidance and coverage visualization.
    \item The server supports both local and cloud GPU processing with automatic lifecycle management.
\end{itemize}

Open items (the FYP-2 schedule for all but mesh creation is in the Remaining FYP Plan chapter):

    \item \textbf{3D mesh creation}: in scope as planned work; not yet scheduled.
    \item \textbf{Structural layer completion}: wall-to-wall dimensions, doors and openings, ceiling-height detection, floor-plan export.
    \item \textbf{Web workspace}: browser viewer with 1:1 measurement.
\end{itemize}
