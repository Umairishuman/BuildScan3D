\chapter{Proposal Feedback and Iteration Plan}

\section{Proposal Feedback Summary}
During the proposal defense, the panel provided the following key feedback:
\begin{itemize}
    \item Clarify the distinction between BuildScan~3D and existing consumer scanning apps (Polycam, Luma AI).
    \item Demonstrate metric accuracy with quantitative comparisons to ground truth measurements.
    \item Focus on measurement accuracy and the automated pipeline rather than feature-rich UI.
    \item Define clear acceptance criteria for reconstruction quality (PSNR, SSIM thresholds).
\end{itemize}

\section{Iteration Strategy}
We follow a two-iteration strategy aligned with FYP-1 and FYP-2:

\begin{itemize}
    \item \textbf{Iteration 1 (FYP-1, Weeks 1--8)}: Core model implementation---capture app, reconstruction pipeline, processing server, cloud GPU integration, validated on real recordings. Status at mid-evaluation: \emph{core pipeline complete, refinement ongoing}. Deliverables: working Android APK, FastAPI server, RunPod integration, metric-accurate 3D reconstruction.
    \item \textbf{Iteration 2 (FYP-2, Weeks 9--16)}: Optimization, performance tuning, and feature enrichment. Deliverables: reduced processing time, pipeline robustness improvements, Three.js web viewer with measurement tools, structural layer and floor plans, field validation on multiple rooms.
\end{itemize}

\section{Iteration 1 Plan}
\begin{itemize}
    \item \textbf{Objective}: Build the end-to-end pipeline from phone capture to 3D model.
    \item \textbf{Features}: ARCore capture with IQA + coverage overlay; COLMAP SfM + splatfacto training; FastAPI server with RunPod dispatch; upload UI in the Android app.
    \item \textbf{Deliverables}: Working Android APK, processing server, cloud GPU integration, reconstruction quality validation on two rooms.
    \item \textbf{Evidence}: Live demo of phone capture $\rightarrow$ upload $\rightarrow$ cloud processing $\rightarrow$ 3D model viewing.
\end{itemize}

\section{Iteration 2 Plan}
\begin{itemize}
    \item \textbf{Objective}: Optimize processing time, improve pipeline robustness, complete the structural layer and add measurement tools.
    \item \textbf{Features}: Pipeline optimization (target $<$35\,min on RTX 4090, projected, from $\sim$75\,min measured on RTX 3070); improved handling of edge cases (mirrors, textureless walls, large rooms); Three.js/WebGPU splat viewer; point-to-point measurement tool that snaps to walls; structural layer completion (wall planes, corners, wall lengths, door detection, floor plans).
    \item \textbf{Deliverables}: Optimized pipeline with reduced processing time, web viewer with measurement tools, structural layer with floor-plan export, field validation report across $\geq$5 rooms.
    \item \textbf{Evidence}: Processing time benchmarks; measurement accuracy comparison with tape-measure ground truth across $\geq$5 rooms.
\end{itemize}

\section{Progress Against Plan}
The core-pipeline milestones of Iteration~1 have been met; refinement is ongoing:
\begin{itemize}
    \item \textbf{Week 1--2}: ARCore capture app with basic recording $\rightarrow$ \textit{Completed}.
    \item \textbf{Week 3--4}: COLMAP SfM pipeline with ARCore Sim3 alignment $\rightarrow$ \textit{Completed}. Also resolved root causes of poor reconstruction quality (tracking gaps, lens distortion, degenerate splats).
    \item \textbf{Week 5--6}: Live IQA, coverage overlay, quality improvements (gyro-aware frame selection, MVS initialization) $\rightarrow$ \textit{Completed}.
    \item \textbf{Week 7--8}: Processing server, RunPod integration, upload UI, CI/CD $\rightarrow$ \textit{Completed}.
    \item \textbf{Open items}: 3DGS refinement, 3D mesh creation, completion of the structural layer, and the web workspace.
\end{itemize}

\section{Delays, Deviations and Recovery Plan}
\begin{itemize}
    \item \textbf{Deviation}: We initially built a custom training script (\texttt{train.py}) with depth supervision, flattening regularization, and pose refinement. After extensive analysis (documented in \texttt{Training\_Analysis.md}), we found this produced worse results than standard splatfacto. We pivoted to using splatfacto for training and keeping our custom preprocessing. This analysis consumed approximately 2 weeks but resulted in a better-informed design decision.
    \item \textbf{Recovery}: The core pipeline is in place, but Iteration~1 is not finished: 3DGS refinement, 3D mesh creation, completion of the structural layer, and the web workspace remain open. The training analysis cost about two weeks. FYP-2 therefore starts with the one-command v6 pipeline and the processing-time reduction, and schedules the structural layer and web workspace in Iterations~2a--2b. 3D mesh creation is in scope but not yet scheduled.
\end{itemize}
